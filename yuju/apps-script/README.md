# yuju Apps Script

yuju 가 쓰는 Google Apps Script 웹앱의 원본. 시트 하나(`104A_zVF_EC...iLjo`)에 붙어 있다.
시트는 비공개이고, 앱은 이 웹앱을 거쳐서만 읽고 쓴다.

앱과 같이 두되 배포에서는 빠진다. 워크플로가 `yuju/` 를 복사할 때 이 디렉터리만
`--exclude` 로 제외하므로 `/yuju/apps-script/` 는 사이트에 올라가지 않는다.
비밀값은 여기 없다. 비밀번호와 기기 토큰은 스크립트 속성에만 있다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `common.gs` | 탭 이름, 기기 인증(`pair`·토큰 확인), 입력 정리(`text_`·`who_`·`id_`), 쓰기 잠금(`withTab_`) |
| `main.gs` | `doPost` 라우터. `cal-ping`(버전 확인)·`pair` 는 토큰 없이 받고, 나머지는 토큰을 확인한 뒤 액션 앞머리로 각 파일에 넘긴다 |
| `read.gs` | `read` — 여러 탭을 한 번에 돌려준다 |
| `note.gs` | `note-add` |
| `voca.gs` | `add` · `fail` · `cleanup` |
| `todo.gs` | `todo-add` · `todo-toggle` |
| `calendar.gs` | `cal-add` · `cal-delete` · `cal-photo` · `cal-photo-delete` |
| `gcal.gs` | 일정·기념일을 구글 캘린더 "희찬❤유주" 에도 띄운다 (yuju → 구글 한 방향) |

## 요청과 응답

입구는 `doPost` 하나다. 몸통은 JSON 이고 `Content-Type: text/plain` 으로 보낸다 —
그래야 브라우저가 사전 요청 없이 보내고, 응답(CORS 열림)을 읽을 수 있다.

```
{"action":"read","tabs":["calendar","note"],"key":"<기기 토큰>"}
→ {"ok":true,"at":1790000000000,"tabs":{"calendar":[["id","date",…],…],"note":[…]}}
```

- 등록된 기기 토큰(`key`)이 없거나 틀리면 무엇을 보내든 `{"ok":false,"error":"unauthorized"}` 다. `doGet` 도 마찬가지다
- 쓰기는 쓰고 난 탭을 `tab` 으로, 그 시각을 `at` 으로 같이 돌려준다. 앱은 다시 읽으러 가지 않고,
  `at` 으로 늦게 도착한 옛 응답을 버린다
- 쓰기는 스크립트 잠금 안에서 한 번에 하나씩 돈다. 행 번호로 지우는 곳이 있어서 겹치면 엉뚱한 줄이 지워진다
- 사용자가 쓴 글은 `text_` 로 앞에 `'` 를 붙여 넣는다. 시트가 `=`·`+`·`-`·`@` 로 시작하는 값을
  수식으로 실행하지 않게 하려는 것이다. 읽을 때는 `'` 없이 나온다

## 기기 인증

기기마다 처음 한 번 숫자 비밀번호 6자리를 누른다. 맞으면 서버가 그 기기 전용 토큰을 주고,
앱은 그 토큰을 기기에 남겨 이후 모든 요청에 싣는다. 평소엔 아무것도 묻지 않는다.

- 비밀번호: 스크립트 속성 `YUJU_PIN` (편집기 → 프로젝트 설정 → 스크립트 속성). **반드시 숫자 6자리** — 키패드가 6자리 숫자만 보낸다.
  비어 있거나 그 꼴이 아니면 아무도 등록 못 하고, 잠금 화면에 "비밀번호가 아직 설정되지 않았어요" 가 뜬다 (실패 횟수는 올라가지 않는다)
- 토큰 목록: 스크립트 속성 `YUJU_TOKENS`. 최근 20개만 남긴다.
  **지우면 모든 기기가 끊긴다** — 다음 요청에서 잠금 화면으로 돌아가고 기기에 남은 데이터도 지운다
- 6자리는 경우의 수가 적어서 요청마다 비밀번호를 받지 않는다. 대신 등록(`pair`)만 비밀번호를 보고,
  1시간에 10번 틀리면 그 1시간 동안 새 기기 등록을 막는다. 이미 등록된 기기는 계속 쓴다
- 비밀번호를 바꿔도 이미 등록된 기기는 그대로다. 같이 끊으려면 `YUJU_TOKENS` 도 지운다

## 고치고 올리는 법

편집기에서 **기존 파일을 열어 ⌘A → ⌘V 로 덮어쓴다.** 새 파일을 만들면 같은 이름이
두 번 선언돼 프로젝트 전체가 SyntaxError 로 죽는다.

배포는 `배포 → 배포 관리 → 편집 → 버전: 새 버전`. 버전을 안 바꾸면 옛 코드가 계속 나간다.
반영됐는지는 `cal-ping` 으로 확인한다. 토큰 없이 버전만 돌려준다.

```
curl -sL "<웹앱 URL>" -H "Content-Type: text/plain" -d '{"action":"cal-ping"}'
```

`-X POST` 는 붙이지 않는다. 리다이렉트 뒤에도 POST 를 유지해서 404 가 난다.

새 배포 URL이 나오면 `yuju/store.js` 의 `YUJU_API` 한 줄만 갈면 된다.
**옛 배포는 반드시 보관 처리한다.** 배포는 만들 때의 코드 버전에 묶여 있어서,
살려두면 인증이 없는 옛 코드가 그 주소로 계속 읽고 쓴다.

## 구글 캘린더 연동

`cal-add` 가 시트에 쓰면서 전용 캘린더 "희찬❤유주" 에도 하루 종일 일정을 만든다.
제목은 `(희찬) …` · `(유주) …` · `(유주희찬) …`, 기념일은 매년 반복이다.
구글 일정 id 는 calendar 탭 8열 `gcal_id` 에 두고 `cal-delete` 가 이걸로 같이 지운다.
구글 캘린더에서 고친 건 yuju 로 돌아오지 않는다.

처음 한 번은 편집기에서 `syncCalendarToGoogle` 을 실행한다. 캘린더 권한 동의 창이 뜨고,
8열 헤더를 붙이고, 기존 일정을 옮긴다. `gcal_id` 가 빈 줄만 처리하므로 다시 돌려도 된다.

## 사진

드라이브 `db/yuju` 에 원본을 두고 "링크가 있는 모든 사용자" 로 공유한다. 달력이 썸네일을
드라이브에서 바로 받아야 빠르기 때문이다. 대신 파일 id 는 등록된 기기만 받을 수 있다.
올라오는 파일은 앞 바이트로 형식을 확인해 이미지(JPEG·PNG·GIF·WEBP·HEIC)만 받는다.

## 겪은 함정

- 파일이 나뉘어도 전역은 하나다. 같은 상수를 두 파일에서 선언하면 프로젝트 전체가 죽는다
- `DriveApp`·`CalendarApp` 은 새 OAuth 범위다. 배포만으로는 동의 창이 안 뜨고, `_` 없는 함수를
  편집기에서 한 번 실행해야 한다. 동의 창에서 일부만 허용하면 실행은 되지만 그 서비스만 조용히 실패한다
- 예외가 새어나가면 웹앱이 HTML 오류 페이지를 돌려준다. `main.gs` 의 `try/catch` 가
  그걸 JSON 으로 바꾼다. 원인을 볼 수 있는 유일한 통로다
