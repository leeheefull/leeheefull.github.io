## 배경

- 숙박 서비스의 인프라 비용이 꾸준히 증가하고 검색 p99 지연·온콜 알람이 잦아졌지만, "서버를 늘리자"는 대응만 반복되고 근본 원인 분석이 없었음
- 비용 최적화 에픽을 발제하고 리드하여, 감(感)이 아닌 **실측 기반으로 증설/최적화 의사결정**을 하는 것을 목표로 설정

## 주요 작업

- **메모리 증설 ROI 분석**: 증설이 요청된 서버를 kubectl/jcmd로 실측해 힙 사용량이 4배 과대평가되었음을 검증 → 증설 대신 '메모리 최적화 우선' 정책으로 결정 유도
- **스레드/커넥션 풀 전수 점검**: 3개 서비스 × 풀 6종(Tomcat, HikariCP, 비동기 executor 등)을 코드 감사 + APM 실측으로 검증하고 적정값 조정
- **검색 성능 근본 원인 규명**: 검색 엔진(ES) 문서 1건 1.5MB 중 **94%가 날짜별 가격/재고 등 휘발성 데이터**이고, 이로 인한 힙 95% 점유·일 300회 이상의 긴급 GC가 p99 지연의 근본 원인임을 입증 — 휘발성 데이터를 분리하는 읽기 모델(CQRS) 설계와 shadow-read 기반 무중단 이행 경로 제시
- **결제 직전 검증 API 지연 장애 원인 분석**: 특정 시점부터 발생한 지연을 추적해, 내부 레이어의 호출 패턴 변화로 특정 API 부하가 6배 증가 → 공유 이벤트루프 경합이 원인임을 규명하고 전사 공유
- **DB 미사용 데이터 파기**: 파기 정책 8종 분류, 보관 기간별 비용 시뮬레이션으로 의사결정 근거 제공, hard delete 배치 개발

## 성과

- 데이터 실측으로 **불필요한 인프라 증설을 보류**시키고 비용 의사결정의 기준을 '측정'으로 전환
- 검색 지연의 근본 원인을 구조 문제로 규명해, 단기 튜닝이 아닌 **아키텍처 개선 로드맵(읽기 모델 분리)** 을 팀 방향으로 확정
- 장애 원인 분석 문서를 전사 공유해 유사 장애의 재발 방지 기준 마련
