## 배경

- 가격비교 채널(네이버 EP)은 숙박의 주요 유입 경로로, 피드 데이터 품질이 곧 유입 트래픽 품질로 직결됨
- 사내 EP 시스템이 V2로 개편되며 숙박 도메인 연동을 담당했고, 운영 중 발견된 중복 발행 문제를 구조적으로 해결

## 주요 작업

- **EP V2 연동** — 숙소 상품의 EP 데이터 생성·변환 로직, 수동 동기화 API 개발
- **중복 발행 이슈 해결** — 같은 숙소가 여러 ID로 피드에 중복 노출되는 문제를 대표 ID 기준 발행(비대표 ID는 비활성 송신)으로 정리
- **전송 이력 레지스트리 도입** — 발행 이력을 유니크 레지스트리 테이블로 관리하도록 로직 전환, 동기화 배치 개선
- 상품 피드 전체 아키텍처(수집→변환→발행 흐름)를 코드 기반으로 역추적해 문서화, EP 운영 가이드 작성

## 성과

- 가격비교 채널의 중복/오노출을 구조적으로 차단해 **피드 데이터 신뢰성 확보**
- 피드 발행 상태를 이력으로 추적할 수 있게 되어 운영 문의 대응 시간 단축
- 담당자가 바뀌어도 유지보수 가능하도록 전 흐름을 문서 자산화
